MAUI - Navigatie & Messaging

In de vorige les bouwden we een MVVM-app met data binding, CollectionView en persistentie via LiteDB. Nu voegen we navigatie toe tussen schermen, en leren we hoe ViewModels met elkaar kunnen communiceren zonder rechtstreekse koppeling.

Navigatie in een MVVM-app

Navigatie is ook logica, dus die willen we liefst niet in de code-behind van de View stoppen. In MAUI met Shell navigeren we meestal met Shell.Current.GoToAsync.

Zonder MVVM zouden we bijvoorbeeld in code-behind doen:

await Shell.Current.GoToAsync(nameof(JokeDetailPage));

In een MVVM-opzet willen we navigatie vanuit een ViewModel kunnen aansturen, zonder een rechtstreekse afhankelijkheid op Shell.Current.

Daarom creëren we een NavigationService waar we Shell-navigatie in plaatsen.

Shell-routes definiëren

Om Shell-navigatie te kunnen gebruiken moet de Shell weet hebben van de pagina’s waarnaar men kan gaan. Dit laat je weten via de routes.

Stel dat we een pagina hebben genaamd JokeDetailPage, dan zou de registratie hiervan als volgt zijn:

Routing.RegisterRoute(nameof(JokeDetailPage), typeof(JokeDetailPage));

Deze registratie gebeurt binnen MauiProgram.cs, in de methode CreateMauiApp.

NavigationService

Zoals gezegd willen we geen harde afhankelijkheid van Shell in onze ViewModellen, dus we gaan de navigatie encapsuleren in een NavigationService. Hiervoor definiëren we eerst een interface:

public interface INavigationService
{
    Task GoToAsync(string route, IDictionary<string, object>? parameters = null);

    Task GoBackAsync();
}

Implementatie op basis van Shell:

public class ShellNavigationService : INavigationService
{
    public async Task GoToAsync(string route, IDictionary<string, object>? parameters = null)
    {
        if (parameters is null)
            await Shell.Current.GoToAsync(route);
        else
            await Shell.Current.GoToAsync(route, parameters);
    }

    public async Task GoBackAsync()
    {
            await Shell.Current.GoToAsync("..");
    }
}

Registratie in MauiProgram.cs:

...
builder.Services.AddTransient<INavigationService, ShellNavigationService>();
...

Navigeren vanuit een ViewModel

Nu kan een ViewModel navigatie vragen via de service (de INotifyPropertyChanged is even weggelaten om te focussen op de navigatie):

public class JokeListViewModel
{
    private readonly IJokeService _jokeService;
    private readonly INavigationService _navigationService;

    public ObservableCollection<JokeViewModel> Jokes { get; init; }

    private JokeViewModel? _selectedJoke;
    public JokeViewModel? SelectedJoke
    {
        get => _selectedJoke;
        set
        {
            _selectedJoke = value;
            OnJokeSelected(value);
        }
    }

    public JokeListViewModel(IJokeService jokeService, INavigationService navigationService)
    {
        _jokeService = jokeService;
        _navigationService = navigationService;

        Jokes = new ObservableCollection<JokeViewModel>();
    }

    private async void OnJokeSelected(JokeViewModel? joke)
    {
        if (joke is null)
            return;

        var parameters = new Dictionary<string, object>
        {
            ["jokeId"] = joke.Id
        };

        await _navigationService.GoToAsync(nameof(JokeDetailPage), parameters);
    }
}

De CollectionView in XAML bindt SelectedItem op dit ViewModel:

<CollectionView ItemsSource="{Binding Jokes}"
                SelectionMode="Single"
                SelectedItem="{Binding SelectedJoke}">
    <CollectionView.ItemTemplate>
        <DataTemplate>
            <Border Padding="10" Margin="4">
                <Label Text="{Binding Text}" />
            </Border>
        </DataTemplate>
    </CollectionView.ItemTemplate>
</CollectionView>

Data doorgeven met IQueryAttributable

Shell kan parameters doorgeven aan de doelpagina. Die parameters komen terecht in een dictionary waar het ViewModel uit kan lezen.

Dit doe je door de ingebouwde MAUI-interface IQueryAttributable te implementeren op het ViewModel. Je schrijft deze interface niet zelf — ze zit in het framework en je implementeert ze gewoon:

// Ingebouwd in MAUI — niet zelf schrijven
public interface IQueryAttributable
{
    void ApplyQueryAttributes(IDictionary<string, object> query);
}

Wanneer we navigeren met:

var parameters = new Dictionary<string, object>
{
    ["jokeId"] = selectedJoke.Id
};

await _navigationService.GoToAsync(nameof(JokeDetailPage), parameters);

dan kunnen we deze parameter opvangen in het ViewModel van JokeDetailPage:

public class JokeDetailViewModel : IQueryAttributable
{
    private readonly IJokeService _jokeService;

    private JokeViewModel? _joke;
    public JokeViewModel? Joke
    {
        ...
    }

    ...

    public void ApplyQueryAttributes(IDictionary<string, object> query)
    {
        if (query.TryGetValue("jokeId", out var value) && value is Guid jokeId)
        {
            var joke = _jokeService.GetById(jokeId);

            if (joke is not null)
                Joke = new JokeViewModel(joke);
        }
    }
}

In de View stellen we dit ViewModel in als BindingContext, net zoals we al gezien hebben:

public partial class JokeDetailPage : ContentPage
{
    public JokeDetailPage(JokeDetailViewModel vm)
    {
        InitializeComponent();
        BindingContext = vm;
    }
}
De key die je gebruikt in de parameters ("jokeId") moet overeenkomen met de key die je gebruikt in ApplyQueryAttributes.

WeakReferenceMessenger

Nu twee schermen actief zijn, rijst de vraag: hoe weet de ene ViewModel dat de andere iets gewijzigd heeft?

Stel: de gebruiker navigeert vanuit JokeListPage naar JokeDetailPage om een grap te verwijderen. Wanneer hij terugkeert, staat de JokeListViewModel nog altijd in het geheugen, maar zijn ObservableCollection weet niets van de wijziging.

Een naiëve oplossing is de data telkens opnieuw laden wanneer het scherm zichtbaar wordt. Dat werkt, maar het schaalt slecht en koppelt de schermen indirect.

Een schonere aanpak: laat de JokeService een bericht sturen zodra er iets veranderd is, en laat de JokeListViewModel naar dat bericht luisteren. De service weet niet wie er luistert, het ViewModel weet niet wie er gestuurd heeft.

WeakReferenceMessenger is een publish/subscribe mechanisme uit het NuGet-pakket CommunityToolkit.Mvvm.

  • Een sender stuurt een bericht via Send.

  • Een ontvanger registreert zich via Register en reageert wanneer het bericht binnenkomt.

Het woord Weak slaat op hoe de messenger de ontvangers bijhoudt: via zwakke referenties. Dit betekent dat de messenger de garbage collector niet belet om een ViewModel op te ruimen wanneer het niet meer actief is. Zo vermijd je geheugenlekken, zonder dat je ontvangers manueel moet afmelden.

NuGet-pakket

Voeg CommunityToolkit.Mvvm toe aan je project via NuGet.

Message-klassen

Een message-klasse is een eenvoudige dataklasse die de informatie bevat die je wil doorgeven.

public class JokeRemovedMessage
{
    public Guid JokeId { get; }

    public JokeRemovedMessage(Guid jokeId)
    {
        JokeId = jokeId;
    }
}

Zet deze klassen bij voorkeur in een aparte map Messages.

Versturen vanuit de service

De JokeService stuurt een bericht na elke relevante actie:

using CommunityToolkit.Mvvm.Messaging;

public class JokeService : IJokeService
{
    ...

    public void Remove(Guid jokeId)
    {
        _repository.Remove(jokeId);

        WeakReferenceMessenger.Default.Send(new JokeRemovedMessage(jokeId));
    }

    ...
}

Ontvangen in het ViewModel

De JokeListViewModel registreert zich in de constructor om berichten te ontvangen:

using CommunityToolkit.Mvvm.Messaging;

public class JokeListViewModel : INotifyPropertyChanged
{
    ...

    public JokeListViewModel(IJokeService jokeService, INavigationService navigationService)
    {
        ...

        WeakReferenceMessenger.Default.Register<JokeRemovedMessage>(this, (sender, message) =>
        {
            var item = Jokes.FirstOrDefault(joke => joke.Id == message.JokeId);
            if (item != null)
                Jokes.Remove(item);
        });
    }
}

Wanneer nu vanuit JokeDetailPage een grap verwijderd wordt, reageert de JokeListViewModel automatisch — zonder dat de twee ViewModels elkaar kennen.

Oefening

Vertrek van de Joke-app uit de vorige les en breid deze uit met navigatie en messaging.

  • Voeg een detailscherm toe waarop een geselecteerde grap uit de CollectionView bewerkt of verwijderd kan worden. Navigeer er naartoe via de NavigationService en geef de geselecteerde grap mee als parameter via IQueryAttributable. Typisch gaan we het id meegeven met de navigation waarop de doel pagina de data ophaalt uit de database.

  • Wanneer een grap bewerkt of verwijderd wordt via de JokeService, moet de CollectionView op het lijstscherm automatisch bijgewerkt worden via WeakReferenceMessenger.

WebAPI

Tot nu toe kwamen grappen uit het geheugen of uit een lokale LiteDB-database. Dankzij DI kunnen we even gemakkelijk overstappen op een volledig andere bron: een WebAPI.

We gebruiken de openbare JokeAPI die gratis grappen aanbiedt. Een willekeurige grap ophalen doe je via:

https://v2.jokeapi.dev/joke/Any?blacklistFlags=nsfw,racist,sexist&type=single

Een typisch antwoord ziet er zo uit:

{
    "category": "Programming",
    "type": "single",
    "joke": "A SQL query walks into a bar, walks up to two tables and asks: 'Can I join you?'",
    "safe": true
}

Response DTO

Om de JSON te deserialiseren, maken we een eenvoudige DTO-klasse. Het attribuut [JsonPropertyName] koppelt de C#-property aan de juiste JSON-sleutel:

using System.Text.Json.Serialization;

public sealed class JokeApiResponse
{
    [JsonPropertyName("joke")]
    public string? Text { get; set; }
}

Een afzonderlijke provider

De externe API kan een nieuwe willekeurige grap aanleveren, maar kan onze lokale grappen niet toevoegen, bewerken of verwijderen. De API is daarom geen volwaardige implementatie van IJokeService.

We modelleren de kleinere verantwoordelijkheid met een afzonderlijk contract.

public interface IRandomJokeProvider
{
    Task<Joke> GetRandomAsync();
}

public sealed class JokeApiProvider : IRandomJokeProvider
{
    private const string ApiUrl =
        "https://v2.jokeapi.dev/joke/Any?blacklistFlags=nsfw,racist,sexist&type=single";

    private readonly HttpClient _httpClient;

    public JokeApiProvider(HttpClient httpClient)
    {
        _httpClient = httpClient;
    }

    public async Task<Joke> GetRandomAsync()
    {
        var response = await _httpClient
            .GetFromJsonAsync<JokeApiResponse>(ApiUrl);

        if (string.IsNullOrWhiteSpace(response?.Text))
            throw new InvalidOperationException(
                "De API gaf geen geldige grap terug.");

        return new Joke(response.Text, JokeCategory.Other);
    }
}

De JokeService kan deze kleinere dependency gebruiken om een suggestie op te halen en vervolgens via de bestaande repository op te slaan. De service blijft zo verantwoordelijk voor de applicatiebewerking.

public async Task<Joke> ImportRandomAsync()
{
    var joke = await _randomJokeProvider.GetRandomAsync();
    Add(joke);
    return joke;
}

Voeg deze methode toe aan IJokeService en injecteer IRandomJokeProvider naast IJokeRepository in de constructor van JokeService.

DI-registratie uitbreiden

Registreer ook de HttpClient en de provider in MauiProgram.cs.

builder.Services.AddSingleton(new HttpClient());
builder.Services.AddTransient<IRandomJokeProvider, JokeApiProvider>();

Het ViewModel blijft uitsluitend via IJokeService werken. Het hoeft niet te weten welke URL wordt aangeroepen of hoe het JSON-antwoord wordt omgezet.

Oefening

Voeg een IRandomJokeProvider toe die grappen ophaalt via de JokeAPI.

  • Laat JokeService een externe grap importeren en via de bestaande repository bewaren.

  • Roep deze bewerking aan via een command op het ViewModel.

  • Toon een zichtbare laad-, succes- en fouttoestand in de UI.

  • De View en het ViewModel mogen geen URL, HttpClient of response-DTO kennen.
