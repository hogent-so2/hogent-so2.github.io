MAUI - MVVM, binding & commands

Startcode nodig? Je vindt de code van vorige les op Github. Heb je zelf een werkende vorige versie, dan is het sterk aangeraden om daarin verder te werken.

Onze JokeApp bewaart haar gegevens via een repository en ontvangt dependencies via DI. De schermen werken nog met events: een handler leest controls uit, roept de service aan en past andere controls aan.

In deze les behouden we de app en vervangen we die communicatie stap voor stap door MVVM. De opslag uit de vorige les blijft ongewijzigd.

Vertrekpunt

Behoud MainPage, AddJokePage, de models, validation-klassen, services, repositories en gedeelde styles. LiteDB blijft geregistreerd. We blijven in dezelfde pagina’s werken en gebruiken de gegevens van de bestaande service.

Open eerst de werkende versie: zoeken, toevoegen, dubbele invoer en opnieuw opstarten moeten werken. Heb je verwijderen als thuisopdracht toegevoegd, bewaar die code; aan het einde migreer je ook die uitbreiding naar MVVM.

Dit is een refactoring. Dezelfde handeling moet voor de gebruiker hetzelfde resultaat blijven geven. Na elke stap controleren we dat, niet pas wanneer alle bestanden vervangen zijn.

Waarom een ViewModel?

Bekijk RefreshJokes en de save-handler. Ze mengen verschillende soorten werk:

  • schermtoestand bijhouden, zoals de toegepaste zoektekst;

  • de service aanroepen;

  • controls aanspreken, zoals countLabel.Text en validationLabel.IsVisible.

Een ViewModel biedt de toestand en acties van een scherm aan zonder zelf labels, editors of pagina’s aan te spreken.

Model

De domeinobjecten, bijvoorbeeld Joke. De tekstregels horen nog steeds bij het domein.

View

De XAML-pagina en haar beperkte code-behind. Ze bepaalt welke controls de toestand presenteren.

ViewModel

Biedt properties en commands voor de View aan. Het gebruikt services voor applicatiegedrag, maar kent geen Label, Editor of ContentPage.

View ── binding ──> ViewModel ──> IJokeService ──> IJokeRepository
                      │
                      └──> INavigationService

De binding wordt in de View gelegd. Het ViewModel krijgt geen verwijzing naar de View. Een property ErrorMessage hoort bijvoorbeeld bij de presentatie; een regel over dubbele grappen blijft in de service.

Binding en BindingContext

In de vorige les gebruikte het DataTemplate al {Binding Text}. Binnen één rij was het bijbehorende Joke-object de bron.

Voor een hele pagina stellen we straks een ViewModel in als BindingContext. Een label met Text="{Binding CountText}" leest dan CountText van dat ViewModel. Child-controls erven die context, behalve waar een control zoals een itemtemplate een eigen context aanbiedt.

Eerst zien waarom een melding nodig is

Probeer tijdelijk onderstaande kleine klasse uit in ViewModels. Stel in MainPage na InitializeComponent() het BindingContext in op new BindingProbeViewModel() en bind één label aan Message. Een tijdelijke button-handler verandert Message in "Gewijzigd".

public sealed class FirstBindingViewModel
{
    public string Message { get; set; } = "Eerste waarde";
}

De eerste waarde verschijnt, maar de latere wijziging wordt niet automatisch zichtbaar. De binding leest een property; ze blijft niet voortdurend alle properties opnieuw opvragen.

Gebruik een breakpoint: is de C#-waarde gewijzigd? Ja. Heeft de UI een melding ontvangen? Nee. Verwijder deze proefklasse en de tijdelijke wijzigingen weer voordat je het echte overzicht aansluit.

INotifyPropertyChanged

INotifyPropertyChanged biedt één event, PropertyChanged. Via de eventgegevens vertel je welke property gewijzigd is.

We brengen de herhaalde code samen in een basisklasse.

ViewModels/ViewModelBase.cs
using System.ComponentModel;
using System.Runtime.CompilerServices;

namespace JokeApp.ViewModels;

public abstract class ViewModelBase : INotifyPropertyChanged
{
    public event PropertyChangedEventHandler? PropertyChanged;

    protected void OnPropertyChanged(
        [CallerMemberName] string? propertyName = null)
    {
        PropertyChanged?.Invoke(
            this, new PropertyChangedEventArgs(propertyName));
    }

    protected bool SetProperty<T>(
        ref T field, T value,
        [CallerMemberName] string? propertyName = null)
    {
        if (EqualityComparer<T>.Default.Equals(field, value))
            return false;

        field = value;
        OnPropertyChanged(propertyName);
        return true;
    }
}

SetProperty vergelijkt de oude en nieuwe waarde, wijzigt het veld en meldt de wijziging. De teruggegeven bool is handig wanneer ook een afgeleide property of command opnieuw bekeken moet worden.

CallerMemberName vult de naam van de aanroepende property in. Zo hoef je niet overal zelf strings als "SearchText" te schrijven. Voor een andere, afgeleide property gebruiken we expliciet nameof(…​).

Binding modes

OneWay

Waarden gaan van de bron naar de UI. Een teller is een typisch voorbeeld.

TwoWay

Ook wijzigingen in de control gaan naar de bron. De tekst van een invoerveld moet naar een ViewModel-property kunnen.

OneTime

De waarde wordt bij het leggen van de binding gelezen, zonder de gewone voortdurende wijzigingsmeldingen te volgen.

OneWayToSource

Waarden gaan van de control naar de bron, zonder de omgekeerde richting.

We vermelden Mode=TwoWay bij invoer expliciet om de bedoeling zichtbaar te maken. Voor Entry.Text en Editor.Text is dit al de standaard. Zie Microsoft: binding modes.

TwoWay betekent niet dat we iedere toetsaanslag moeten valideren of bewaren. De invoer gaat naar een formulierproperty. De command achter Opslaan beslist wanneer we valideren en de service aanroepen.

Van een event naar een command

Een button kan in plaats van Clicked een Command krijgen. Het ViewModel biedt de actie aan via ICommand.

Een command heeft twee belangrijke vragen:

Execute

Wat moet gebeuren wanneer de gebruiker de actie uitvoert?

CanExecute

Is de actie op dit moment beschikbaar?

We gebruiken de ingebouwde MAUI-Command. Voor binding en commands installeren we geen extra package.

Neem Task, async en await in de navigatievoorbeelden als een vast recept over. De command roept zo’n methode aan via new Command(async () ⇒ await …​). Asynchroon programmeren wordt buiten deze reeks behandeld. Geef een methode die Task teruggeeft niet rechtstreeks aan new Command door; de callbackvorm hoort bij het recept.

Navigatie zonder een pagina in het ViewModel

De event handler sprak rechtstreeks Shell.Current aan. We willen die kennis niet naar het ViewModel kopiëren.

Maak een kleine navigatieservice met de acties die we nu nodig hebben. Een algemeen contract voor elk denkbaar soort navigatie is niet nodig.

Navigation/INavigationService.cs
namespace JokeApp.Navigation;

public interface INavigationService
{
    Task ShowAddJokeAsync();
    Task GoBackAsync();
}
Navigation/ShellNavigationService.cs
namespace JokeApp.Navigation;

public sealed class ShellNavigationService : INavigationService
{
    public Task ShowAddJokeAsync() =>
        Shell.Current.GoToAsync(nameof(AddJokePage));

    public Task GoBackAsync() =>
        Shell.Current.GoToAsync("..");
}

De service kent Shell en de routenaam; het ViewModel kent alleen de bedoeling. De route in AppShell en de DI-registratie van AddJokePage blijven behouden.

Het overzicht omzetten

We houden twee waarden uit elkaar: SearchText is wat momenteel in het veld staat; _appliedSearchText is de zoekopdracht die de gebruiker werkelijk heeft uitgevoerd. Terugkeren van het formulier mag niet stilzwijgend een nog niet uitgevoerde zoektekst toepassen.

ViewModels/JokeListViewModel.cs
using System.Collections.ObjectModel;
using System.Windows.Input;
using JokeApp.Models;
using JokeApp.Navigation;
using JokeApp.Services;

namespace JokeApp.ViewModels;

public sealed class JokeListViewModel : ViewModelBase
{
    private readonly IJokeService _jokeService;
    private string _searchText = string.Empty;
    private string _appliedSearchText = string.Empty;
    private string _countText = string.Empty;
    private Joke? _selectedJoke;

    public ObservableCollection<Joke> Jokes { get; } = new();

    public string SearchText
    {
        get => _searchText;
        set => SetProperty(ref _searchText, value);
    }

    public string CountText
    {
        get => _countText;
        private set => SetProperty(ref _countText, value);
    }

    public Joke? SelectedJoke
    {
        get => _selectedJoke;
        set
        {
            if (SetProperty(ref _selectedJoke, value))
                OnPropertyChanged(nameof(SelectedJokeText));
        }
    }

    public string SelectedJokeText =>
        SelectedJoke?.Text ?? "Selecteer een grap.";

    public ICommand SearchCommand { get; }
    public ICommand ShowAllCommand { get; }
    public ICommand AddJokeCommand { get; }

    public JokeListViewModel(
        IJokeService jokeService,
        INavigationService navigationService)
    {
        _jokeService = jokeService;
        SearchCommand = new Command(ApplySearch);
        ShowAllCommand = new Command(ShowAll);
        AddJokeCommand = new Command(async () => await navigationService.ShowAddJokeAsync());
    }

    public void Reload()
    {
        var matchingJokes = _jokeService.Search(_appliedSearchText);
        SelectedJoke = null;
        Jokes.Clear();

        foreach (var joke in matchingJokes)
            Jokes.Add(joke);

        CountText = $"{Jokes.Count} van {_jokeService.GetAll().Count} grappen";
    }

    private void ApplySearch()
    {
        _appliedSearchText = SearchText.Trim();
        Reload();
    }

    private void ShowAll()
    {
        SearchText = string.Empty;
        _appliedSearchText = string.Empty;
        Reload();
    }
}

Volg eerst alleen SearchCommand: klik, ApplySearch, service, collectie en teller. Bekijk daarna de selectie. Wanneer SelectedJoke verandert, moet ook SelectedJokeText opnieuw gelezen worden; daarom melden we beide properties.

We tonen hier de modellen rechtstreeks in de lijst. Een extra ViewModel per rij is pas nodig wanneer een rij eigen presentatietoestand of gedrag krijgt. Maak niet automatisch een extra klasse voor drie properties die je alleen kopieert.

Wat ObservableCollection wel en niet doet

De CollectionView luistert naar wijzigingen in ObservableCollection<T>. Add, Remove en Clear kunnen daardoor de zichtbare rijen bijwerken zonder telkens een andere ItemsSource in te stellen.

Maar:

  • een insert in LiteDB roept niet automatisch Jokes.Add aan;

  • een wijziging van Joke.Text is geen wijziging van de collectie;

  • de modellen in onze lijst implementeren geen INotifyPropertyChanged.

Daarom laden we de gegevens voorlopig opnieuw wanneer het overzicht verschijnt. Reload leest de repository via de service en past vervolgens de observeerbare collectie aan. Dit is een bewuste synchronisatiestap, geen automatische databasebinding.

Voor een kleine lokale lijst is opnieuw laden een prima keuze. In de volgende les bekijken we wanneer een expliciet bericht nuttig wordt. Zie ook Microsoft: ObservableCollection.

De View koppelen

Vervang de basisversie van MainPage.xaml door deze versie. De layout en styles blijven herkenbaar; namen en event handlers maken plaats voor bindings. Bewaar je eigen verwijderknop voor de thuisopdracht.

x:DataType vertelt de XAML-compiler welk type een binding verwacht. Op de pagina is dat JokeListViewModel, in het itemtemplate Joke. Het maakt zelf geen object en vervangt BindingContext niet.

MainPage.xaml.cs
using JokeApp.ViewModels;

namespace JokeApp;

public partial class MainPage : ContentPage
{
    private readonly JokeListViewModel _viewModel;

    public MainPage(JokeListViewModel viewModel)
    {
        InitializeComponent();
        _viewModel = viewModel;
        BindingContext = viewModel;
    }

    protected override void OnAppearing()
    {
        base.OnAppearing();
        _viewModel.Reload();
    }
}

Code-behind is niet verboden. Een lifecycle-event van een pagina doorgeven is iets anders dan de validatieregels of opslag daar implementeren.

Voeg using JokeApp.Navigation; en using JokeApp.ViewModels; toe aan MauiProgram.cs en registreer vóór Build():

builder.Services.AddTransient<INavigationService, ShellNavigationService>();
builder.Services.AddTransient<JokeListViewModel>();

De bestaande registraties van services, repositories en pagina’s blijven staan; registreer ze niet dubbel. Test nu het overzicht. Het toevoegscherm werkt op dit tussenpunt nog met zijn bestaande code-behind.

Het toevoegformulier omzetten

We gebruiken gewone properties voor formulierinvoer. Een lege Text mag bestaan in dit ViewModel: de gebruiker heeft nog niets opgeslagen.

De setter van het model blijft ongeldige modeltoestand tegenhouden. De setter van het formulier bewaart wat de gebruiker typt en wist eventueel een oude foutmelding. Die setter probeert nog geen Joke te wijzigen.

ViewModels/AddJokeViewModel.cs
using System.Windows.Input;
using JokeApp.Models;
using JokeApp.Navigation;
using JokeApp.Services;
using JokeApp.Validation;

namespace JokeApp.ViewModels;

public sealed class AddJokeViewModel : ViewModelBase
{
    private readonly IJokeService _jokeService;
    private readonly INavigationService _navigationService;
    private string _text = string.Empty;
    private JokeCategory _selectedCategory = JokeCategory.Programming;
    private string _errorMessage = string.Empty;

    public IReadOnlyList<JokeCategory> Categories { get; } =
        Enum.GetValues<JokeCategory>();

    public string Text
    {
        get => _text;
        set
        {
            if (SetProperty(ref _text, value))
                ErrorMessage = string.Empty;
        }
    }

    public JokeCategory SelectedCategory
    {
        get => _selectedCategory;
        set => SetProperty(ref _selectedCategory, value);
    }

    public string ErrorMessage
    {
        get => _errorMessage;
        private set
        {
            if (SetProperty(ref _errorMessage, value))
                OnPropertyChanged(nameof(HasError));
        }
    }

    public bool HasError => ErrorMessage.Length > 0;
    public ICommand SaveCommand { get; }

    public AddJokeViewModel(
        IJokeService jokeService,
        INavigationService navigationService)
    {
        _jokeService = jokeService;
        _navigationService = navigationService;
        SaveCommand = new Command(async () => await SaveAsync());
    }

    private async Task SaveAsync()
    {
        ErrorMessage = string.Empty;
        var validation = JokeTextValidator.Validate(Text);

        if (!validation.IsValid)
        {
            ErrorMessage = validation.ErrorMessage;
            return;
        }

        var joke = new Joke(Text, SelectedCategory);
        var addResult = _jokeService.Add(joke);

        if (!addResult.IsValid)
        {
            ErrorMessage = addResult.ErrorMessage;
            return;
        }

        await _navigationService.GoBackAsync();
    }
}

Voeg nu ook builder.Services.AddTransient<AddJokeViewModel>(); toe vóór Build() in MauiProgram. De pagina gaat dit ViewModel straks via haar constructor ontvangen.

Vergelijk SaveAsync regel voor regel met de vorige event handler. De beslissingen blijven dezelfde. ShowValidationError wordt een waarde in ErrorMessage; terugkeren verloopt via de navigatieservice.

De categorie heeft een geldige beginwaarde en de picker biedt alleen enumwaarden aan. We vragen hier geen vrije tekst voor een categorie.

De View verwijdert dus niet de validatie. Ze presenteert het resultaat ervan via binding. Een gewenste focusverplaatsing is wel View-gedrag; laat een ViewModel daarvoor geen Editor ontvangen.

De volledige weg van één klik

Volg met breakpoints een lege, een geldige en een dubbele invoer:

  1. De editor werkt Text bij via TwoWay.

  2. De gebruiker klikt op Opslaan.

  3. SaveCommand voert SaveAsync uit.

  4. De gedeelde validator controleert de tekst.

  5. Alleen bij geldige invoer maken we het model.

  6. De service controleert uniciteit en laat de repository bewaren.

  7. Bij een fout verandert ErrorMessage; bij succes keren we terug.

  8. OnAppearing laat het overzicht opnieuw laden.

Let op: een lege tekst moet vóór de klik nog geen foutmelding opleveren. Een foutmelding verdwijnt wanneer de gebruiker de tekst aanpast; we voeren dan niet opnieuw de volledige validatie uit.

Testen zonder het scherm te bedienen

Het ViewModel krijgt interfaces. Daardoor kan een test een in-memory repository en een navigatieservice gebruiken die alleen bijhoudt of terugkeren gevraagd werd.

Een mogelijke testdouble:

using JokeApp.Navigation;

public class RecordingNavigationService : INavigationService
{
    public int BackCount { get; private set; }

    public Task ShowAddJokeAsync() => Task.CompletedTask;

    public Task GoBackAsync()
    {
        BackCount++;
        return Task.CompletedTask;
    }
}

Voer in een testproject of begeleide test onderstaande controles uit via SaveCommand.Execute(null).

Deze recording navigation service geeft onmiddellijk een voltooide Task terug. De validatie en opslag zijn hier ook synchroon. Daardoor kunnen we in deze tests meteen na Execute(null) de toestand controleren. Een gewone Command biedt zelf geen methode om een asynchrone uitvoering af te wachten; trek uit deze testopstelling dus geen algemene conclusie over echte navigatie of netwerkverzoeken.

  • Lege tekst: HasError is waar, aantal grappen blijft gelijk en BackCount blijft nul.

  • Geldige unieke tekst: aantal grappen stijgt met één en BackCount stijgt met één.

  • Dubbele tekst: melding verschijnt, aantal grappen en BackCount stijgen niet.

  • Na een fout de tekst aanpassen: oude melding verdwijnt, er wordt nog niets bewaard.

  • Zoeken: de resultaten veranderen pas wanneer het zoekcommand uitgevoerd wordt.

Het doel is de verantwoordelijkheid kunnen testen, niet in deze les een nieuw testframework aanleren.

Thuisopdracht - Ook je eigen uitbreiding via MVVM

Vertrek van de gemigreerde JokeApp. Breng de verwijderfunctie uit de vorige thuisopdracht over naar deze structuur en werk de feedback af.

Must

  • Voeg DeleteJokeCommand toe aan JokeListViewModel en bind je verwijderknop eraan.

  • Laat CanExecute afhangen van SelectedJoke. Bewaar de concrete Command zodat je ChangeCanExecute() kan aanroepen wanneer de selectie verandert.

  • Roep IJokeService.Remove aan, toon een mislukt resultaat via een gebonden StatusMessage en vernieuw bij succes de lijst en teller.

  • Behoud de toegepaste zoektekst, wis de oude selectie en geef ook bij succes een korte bevestiging.

  • Voeg in AddJokeViewModel een afgeleide CharacterCountText toe en bind er een label aan. Meld die property mee wanneer Text wijzigt. Een teller is informatie, geen continue validatie; Opslaan blijft beschikbaar bij lege of te lange invoer.

Should

  • Behoud een eventuele bevestigingsdialoog via een klein servicecontract; laat het ViewModel geen pagina opzoeken.

  • Controleer met breakpoints dat PropertyChanged de juiste propertynamen meldt.

  • Test een zoekopdracht zonder resultaten en het verwijderen van de laatste grap met beide repositories.

Could

  • Voeg een command toe dat het formulier wist en de standaardcategorie herstelt, zonder iets op te slaan.

  • Schrijf de beschreven tests met een recording navigation service.

Controle vóór de volgende les

Zoeken, toevoegen en verwijderen werken met binding en commands. De invoer wordt bij Opslaan gevalideerd, de styles zijn behouden en de gegevens overleven een herstart. In ViewModels staan geen namen van controls of concrete repositories.

Bewaar deze versie. In de volgende les openen en bewerken we een bestaande grap. We breiden de navigatieservice uit en bekijken hoe onderdelen elkaar over een bewaarde wijziging kunnen informeren.
