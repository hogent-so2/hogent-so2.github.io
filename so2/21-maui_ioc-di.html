MAUI - Inversion of Control & Dependency Injection

Onze JokeApp bestaat intussen uit meerdere pagina’s. MainPage maakt zelf een AddJokePage en geeft de JokeService manueel door. Dit werkt, maar de pagina bepaalt daardoor zelf welke concrete objecten worden aangemaakt en hoe lang ze blijven bestaan.

In deze les gebruiken we Inversion of Control en Dependency Injection om die verantwoordelijkheid te verplaatsen.

Het huidige ontwerp

In de vorige versie maakt de pagina haar dependency zelf.

public partial class MainPage : ContentPage
{
    private readonly JokeService _jokeService = new();

    // ...

    private async void OnAddJokeClicked(object? sender, EventArgs e)
    {
        var addJokePage = new AddJokePage(_jokeService);
        await Navigation.PushAsync(addJokePage);
    }
}

MainPage heeft hierdoor meerdere redenen om te wijzigen:

  • de interactie op het overzichtsscherm verandert;

  • een andere implementatie van de service wordt gekozen;

  • de constructor van AddJokePage verandert;

  • de levensduur van de service verandert.

De pagina draagt verantwoordelijkheden die niet bij de presentatie van het overzicht horen.

Inversion of Control

Inversion of Control of IoC betekent dat een object niet langer zelf de volledige controle heeft over het verkrijgen van zijn dependencies.

Zelf de dependency maken

public sealed class JokeService
{
    private readonly JokeRepository _jokeRepository = new();
}

De service kiest hier zelf:

  • de concrete klasse JokeRepository;

  • het moment waarop de repository ontstaat;

  • de levensduur van de repository.

Dit zorgt voor een sterke koppeling.

De dependency ontvangen

public sealed class JokeService : IJokeService
{
    private readonly IJokeRepository _jokeRepository;

    public JokeService(IJokeRepository jokeRepository)
    {
        _jokeRepository = jokeRepository;
    }
}

JokeService vraagt wat hij nodig heeft via zijn constructor. De klasse kent alleen het contract IJokeRepository en beslist niet langer welke implementatie gebruikt wordt.

Dit is constructor injection: de dependency wordt via de constructor geïnjecteerd.

Repository

Een repository biedt toegang tot een collectie domeinobjecten zonder dat de gebruiker ervan moet weten hoe of waar ze bewaard worden.

public interface IJokeRepository
{
    IReadOnlyList<Joke> GetAll();
    Joke? GetById(Guid id);
    void Add(Joke joke);
    void Remove(Guid id);
}

De eerste implementatie bewaart alles in het geheugen.

public sealed class InMemoryJokeRepository : IJokeRepository
{
    private readonly List<Joke> _jokes = new()
    {
        new Joke(
            "Er zijn 10 soorten mensen: zij die binair begrijpen en zij die dat niet doen.",
            JokeCategory.Programming),
        new Joke(
            "Een SQL-query stapt naar twee tabellen en vraagt: mag ik erbij komen?",
            JokeCategory.Programming)
    };

    public IReadOnlyList<Joke> GetAll()
    {
        return _jokes.AsReadOnly();
    }

    public Joke? GetById(Guid id)
    {
        return _jokes.SingleOrDefault(joke => joke.Id == id);
    }

    public void Add(Joke joke)
    {
        ArgumentNullException.ThrowIfNull(joke);
        _jokes.Add(joke);
    }

    public void Remove(Guid id)
    {
        var joke = GetById(id);

        if (joke is not null)
            _jokes.Remove(joke);
    }
}

Service

De repository bewaart objecten. De service coördineert de applicatieregels.

public interface IJokeService
{
    IReadOnlyList<Joke> GetAll();
    Joke? GetById(Guid id);
    Joke GetRandom();
    void Add(Joke joke);
    void Remove(Guid id);
}

public sealed class JokeService : IJokeService
{
    private readonly IJokeRepository _jokeRepository;

    public JokeService(IJokeRepository jokeRepository)
    {
        _jokeRepository = jokeRepository;
    }

    public IReadOnlyList<Joke> GetAll()
    {
        return _jokeRepository.GetAll();
    }

    public Joke? GetById(Guid id)
    {
        return _jokeRepository.GetById(id);
    }

    public Joke GetRandom()
    {
        var jokes = _jokeRepository.GetAll();

        if (jokes.Count == 0)
            throw new InvalidOperationException(
                "Er zijn geen grappen beschikbaar.");

        return jokes[Random.Shared.Next(jokes.Count)];
    }

    public void Add(Joke joke)
    {
        ArgumentNullException.ThrowIfNull(joke);

        var alreadyExists = _jokeRepository
            .GetAll()
            .Any(existingJoke => string.Equals(
                existingJoke.Text,
                joke.Text,
                StringComparison.OrdinalIgnoreCase));

        if (alreadyExists)
            throw new InvalidOperationException(
                "Deze grap bestaat al.");

        _jokeRepository.Add(joke);
    }

    public void Remove(Guid id)
    {
        _jokeRepository.Remove(id);
    }
}

De verantwoordelijkheden zijn nu duidelijk verdeeld:

Joke

Bewaakt de geldigheid van één grap.

IJokeRepository

Beschrijft hoe grappen opgezocht en bewaard kunnen worden.

JokeService

Past regels toe op bewerkingen met grappen.

Pagina

Presenteert informatie en vertaalt interactie naar aanroepen op IJokeService.

Dependency Injection

Dependency Injection of DI is een concrete manier om IoC toe te passen. Een container kent de beschikbare types en kan objectgrafen opbouwen.

Wanneer MainPage een IJokeService vraagt en JokeService op zijn beurt een IJokeRepository vraagt, kan de container alle objecten in de juiste volgorde maken.

MainPage
└── IJokeService → JokeService
    └── IJokeRepository → InMemoryJokeRepository

Registratie

We registreren de types in MauiProgram.CreateMauiApp() voordat Build() wordt aangeroepen.

public static class MauiProgram
{
    public static MauiApp CreateMauiApp()
    {
        var builder = MauiApp.CreateBuilder();

        builder
            .UseMauiApp<App>()
            .ConfigureFonts(fonts =>
            {
                fonts.AddFont(
                    "OpenSans-Regular.ttf",
                    "OpenSansRegular");
            });

        builder.Services.AddSingleton<
            IJokeRepository,
            InMemoryJokeRepository>();

        builder.Services.AddTransient<
            IJokeService,
            JokeService>();

        builder.Services.AddTransient<MainPage>();
        builder.Services.AddTransient<AddJokePage>();

        return builder.Build();
    }
}

De container kent nu de mappings van interfaces naar concrete implementaties.

Levensduur

AddTransient

Bij iedere resolution wordt een nieuwe instantie gemaakt.

AddSingleton

Dezelfde instantie wordt gedurende de volledige levensduur van de applicatie gedeeld.

AddScoped

Dezelfde instantie wordt binnen één scope gedeeld. Een gewone MAUI-app heeft niet automatisch een request-scope zoals een webapplicatie.

De in-memory repository is een singleton. Anders zou een nieuwe repository ook telkens opnieuw met de startgrappen beginnen. De service zelf bevat geen langlevende toestand en kan transient zijn.

Kies een levensduur op basis van de verantwoordelijkheid en toestand van de klasse. Registreer niet gedachteloos alles als singleton.

Injectie in een pagina

De pagina vraagt nu de interface in haar constructor.

public partial class MainPage : ContentPage
{
    private readonly IJokeService _jokeService;

    public MainPage(IJokeService jokeService)
    {
        InitializeComponent();
        _jokeService = jokeService;
    }

    private void OnShowRandomJokeClicked(
        object? sender,
        EventArgs e)
    {
        var joke = _jokeService.GetRandom();
        currentJokeLabel.Text = joke.Text;
    }
}

MainPage maakt geen concrete JokeService meer. Ook AddJokePage kan op dezelfde manier IJokeService ontvangen.

Pagina’s laten maken door Shell

Voor een detailpagina registreren we een route, bijvoorbeeld in de constructor van AppShell.

public AppShell()
{
    InitializeComponent();

    Routing.RegisterRoute(
        nameof(AddJokePage),
        typeof(AddJokePage));
}

Vervolgens navigeren we naar de route in plaats van zelf new AddJokePage(…​) te schrijven.

private async void OnAddJokeClicked(object? sender, EventArgs e)
{
    await Shell.Current.GoToAsync(nameof(AddJokePage));
}

Tijdens Shell-navigatie kan MAUI de geregistreerde pagina via de container maken en haar dependencies injecteren.

Waarom een interface?

Een interface is vooral waardevol wanneer meerdere implementaties nuttig zijn of wanneer een afhankelijkheid aan de buitenkant van een component ligt.

Voor IJokeRepository verwachten we meerdere implementaties:

  • opslag in het geheugen;

  • opslag in LiteDB;

  • eventueel opslag via een externe service.

JokeService hoeft niet te wijzigen wanneer de repository wisselt. Dat is een concrete toepassing van Protected Variations en Low Coupling uit GRASP.

Maak niet voor iedere klasse automatisch een interface. Een interface zonder variatie, contract of testreden voegt voornamelijk extra bestanden toe.

Oefening - JokeApp via DI

Vertrek van de grappenapp uit de vorige les. Het gedrag en de vormgeving moeten behouden blijven.

Must

  • Definieer IJokeRepository en implementeer InMemoryJokeRepository.

  • Laat JokeService de repository via constructor injection ontvangen.

  • Definieer IJokeService en laat de pagina’s uitsluitend van die interface afhangen.

  • Registreer repository, service en pagina’s met passende lifetimes.

  • Verwijder alle new JokeService()-aanroepen uit de pagina’s.

  • Navigeer naar AddJokePage via een geregistreerde Shell-route.

  • Controleer dat toegevoegde grappen zichtbaar blijven bij navigatie tussen pagina’s.

Should

  • Voeg een DadJokeRepository toe met een andere vaste reeks grappen.

  • Wissel in MauiProgram van repository zonder pagina’s of JokeService te wijzigen.

  • Laat de gekozen repository ook verwijderen op basis van de Id van een grap.

Could

  • Schrijf een kleine fake repository en gebruik die in een unit test voor JokeService.

  • Test dat de service dubbele grappen weigert.

  • Groepeer de registraties in duidelijke extension methods zoals RegisterServices() en RegisterPages().

Controleer bij iedere new in een pagina of de pagina werkelijk verantwoordelijk is voor het maken van dat object.
