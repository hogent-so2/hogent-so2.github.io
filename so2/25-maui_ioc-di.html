MAUI - IoC, Dependency Injection & opslag

Startcode nodig? Je vindt de code van vorige les op Github. Heb je zelf een werkende vorige versie, dan is het sterk aangeraden om daarin verder te werken.

We bouwen verder aan dezelfde JokeApp uit Layout, styling & validatie. De gebruiker kan grappen bekijken, zoeken en toevoegen. In deze les verandert vooral de binnenkant: we verdelen verantwoordelijkheden en bewaren de grappen uiteindelijk op schijf.

Vertrekpunt en werkafspraken

Behoud Models/Joke.cs, JokeCategory, JokeTextValidator en ValidationResult uit de vorige les. Ook de styles blijven bestaan. We starten geen nieuw project en keren niet terug naar het scherm met één willekeurige grap.

De thuisopdracht voegde zoeken toe. We gebruiken hiervoor vanaf nu Search(string? searchText) op de service. Heb je een andere methodenaam gekozen, pas dan de aanroep en het contract samen aan.

De validatieafspraak verandert niet: klik op Opslaan, valideer de invoer, maak pas daarna een Joke en vraag de service om die toe te voegen. Een dubbele grap geeft een ValidationResult terug; we keren niet terug naar exceptions als normale formulierfeedback.

We werken in controleerbare stappen: eerst opslag losmaken, dan dependencies laten aanmaken en ten slotte de opslag vervangen. Start de app na iedere stap.

Wie is waarvoor verantwoordelijk?

In de huidige versie bevat JokeService zowel de lijst als de regel dat dezelfde tekst niet tweemaal mag voorkomen. MainPage maakt bovendien zelf de service en de toevoegpagina.

Bespreek wat er zou moeten wijzigen als de grappen niet langer in een List<Joke> maar in een bestand bewaard worden. Moet een pagina daarvoor worden aangepast? Moet de regel over dubbele grappen veranderen?

We maken dit onderscheid:

Joke

Bewaakt de geldigheid van één grap. De setter beschermt bijvoorbeeld de tekst.

JokeService

Coördineert bewerkingen en bewaakt regels over meerdere grappen, zoals uniciteit.

Repository

Zoekt, bewaart en verwijdert grappen. We verbergen de concrete opslag achter een contract.

Pagina

Toont informatie en verwerkt interactie. Voorlopig gebeurt dit nog met code-behind.

Dit sluit aan bij Information Expert en Low Coupling: kennis over opslag hoort bij de repository, kennis over een scherm bij de pagina.

Een contract voor opslag

Maak de map Repositories. We beginnen met de bewerkingen die onze app nodig heeft, niet met een algemene repository voor alle mogelijke toepassingen.

Repositories/IJokeRepository.cs
using JokeApp.Models;

namespace JokeApp.Repositories;

public interface IJokeRepository
{
    IReadOnlyList<Joke> GetAll();
    Joke? GetById(Guid id);
    void Add(Joke joke);
    bool Remove(Guid id);
}

GetById kan null teruggeven: de gevraagde grap bestaat mogelijk niet meer. Remove meldt met een bool of er werkelijk iets verwijderd werd. Een ontbrekende grap is hier geen programmeerfout waarvoor we moeten throwen.

IReadOnlyList<Joke> biedt geen Add-methode. Dat maakt de objecten in die lijst niet automatisch onveranderlijk: het contract schermt de collectie af. Wijzigingen laten we via de service verlopen.

Eerst dezelfde opslag, anders georganiseerd

Verplaats de startgrappen uit JokeService naar onderstaande klasse. Gebruik gerust je eigen geldige startgrappen.

Repositories/InMemoryJokeRepository.cs
using JokeApp.Models;

namespace JokeApp.Repositories;

public sealed class InMemoryJokeRepository : IJokeRepository
{
    private readonly List<Joke> _jokes =
    [
        new Joke(
            "Er zijn 10 soorten mensen: zij die binair begrijpen en zij die dat niet doen.",
            JokeCategory.Programming),
        new Joke(
            "Een SQL-query stapt naar twee tabellen en vraagt: mag ik erbij komen?",
            JokeCategory.Programming),
        new Joke(
            "Ik vertelde een grap over papier, maar die was nogal plat.",
            JokeCategory.DadJoke)
    ];

    public IReadOnlyList<Joke> GetAll() => _jokes.AsReadOnly();

    public Joke? GetById(Guid id) =>
        _jokes.SingleOrDefault(joke => joke.Id == id);

    public void Add(Joke joke)
    {
        ArgumentNullException.ThrowIfNull(joke);
        _jokes.Add(joke);
    }

    public bool Remove(Guid id)
    {
        var joke = GetById(id);
        return joke is not null && _jokes.Remove(joke);
    }
}

Waarom controleert Add hier niet op dezelfde tekst? Dat is een applicatieregel, geen bijzonderheid van een List. Straks moet die regel ook met een andere opslag gelden.

De service ontvangt zijn dependency

Maak het servicecontract en vervang daarna de bestaande JokeService. Voeg geen tweede klasse met dezelfde naam toe.

Services/IJokeService.cs
using JokeApp.Models;
using JokeApp.Validation;

namespace JokeApp.Services;

public interface IJokeService
{
    IReadOnlyList<Joke> GetAll();
    IReadOnlyList<Joke> Search(string? searchText);
    Joke? GetById(Guid id);
    ValidationResult Add(Joke joke);
    ValidationResult Remove(Guid id);
}
Services/JokeService.cs
using JokeApp.Models;
using JokeApp.Repositories;
using JokeApp.Validation;

namespace JokeApp.Services;

public sealed class JokeService : IJokeService
{
    private readonly IJokeRepository _jokeRepository;

    public JokeService(IJokeRepository jokeRepository)
    {
        _jokeRepository = jokeRepository;
    }

    public IReadOnlyList<Joke> GetAll() => _jokeRepository.GetAll();

    public IReadOnlyList<Joke> Search(string? searchText)
    {
        var query = searchText?.Trim() ?? string.Empty;

        return _jokeRepository.GetAll()
            .Where(joke => joke.Text.Contains(
                query, StringComparison.OrdinalIgnoreCase))
            .ToList();
    }

    public Joke? GetById(Guid id) => _jokeRepository.GetById(id);

    public ValidationResult Add(Joke joke)
    {
        ArgumentNullException.ThrowIfNull(joke);

        var duplicateExists = _jokeRepository.GetAll().Any(existing =>
            string.Equals(existing.Text, joke.Text,
                StringComparison.OrdinalIgnoreCase));

        if (duplicateExists)
            return ValidationResult.Failure("Deze grap bestaat al.");

        _jokeRepository.Add(joke);
        return ValidationResult.Success();
    }

    public ValidationResult Remove(Guid id)
    {
        if (!_jokeRepository.Remove(id))
            return ValidationResult.Failure("Deze grap bestaat niet meer.");

        return ValidationResult.Success();
    }
}

Search geeft een nieuwe lijst met resultaten, maar verwijdert niets uit de repository. Een lege zoektekst komt in iedere tekst voor en levert dus alle grappen op.

De oude GetRandom-methode is niet nodig voor het huidige overzicht. Had je die als uitbreiding behouden, laat ze dan eveneens via de repository werken; voeg geen tweede lijst toe.

Dependency Injection zonder container

De service maakt geen new InMemoryJokeRepository(). Hij ontvangt een IJokeRepository. Dat heet constructor injection: de dependency wordt via de constructor doorgegeven.

Je kan deze objecten zelf samenstellen, bijvoorbeeld in een aparte consoleproef of test:

IJokeRepository repository = new InMemoryJokeRepository();
IJokeService service = new JokeService(repository);

var before = service.GetAll().Count;
var joke = new Joke(
    "Waarom houdt een programmeur van koffie? Omdat Java hem wakker houdt.",
    JokeCategory.Programming);

var firstResult = service.Add(joke);
var duplicateResult = service.Add(
    new Joke(joke.Text.ToUpperInvariant(), joke.Category));

Console.WriteLine(firstResult.IsValid);          // True
Console.WriteLine(duplicateResult.ErrorMessage);  // Deze grap bestaat al.
Console.WriteLine(service.GetAll().Count == before + 1); // True

Dit is al DI. Daar is geen framework voor nodig. Inversion of Control is het ruimere principe: de service kiest niet langer zelf hoe zijn dependencies worden gemaakt. Een DI-container zal het samenstellen straks overnemen.

Voer deze proef samen uit en voorspél de uitkomst voordat je ze start. Voeg ook een zoekopdracht en het verwijderen van een onbekende Guid toe. Geen van die proeven heeft een venster nodig.

De container stelt de objecten samen

De container moet weten welke concrete klasse bij een interface hoort.

MainPage
└── IJokeService → JokeService
    └── IJokeRepository → InMemoryJokeRepository

AddJokePage
└── IJokeService → JokeService
    └── IJokeRepository → dezelfde InMemoryJokeRepository

Voeg bovenaan MauiProgram.cs de namespaces JokeApp.Repositories en JokeApp.Services toe. Voeg deze registraties toe vóór return builder.Build();. Behoud de bestaande configuratie van fonts en logging.

builder.Services.AddSingleton<IJokeRepository, InMemoryJokeRepository>();
builder.Services.AddTransient<IJokeService, JokeService>();
builder.Services.AddTransient<MainPage>();
builder.Services.AddTransient<AddJokePage>();
AddSingleton

Eén instantie per container. Onze pagina’s moeten dezelfde in-memory gegevens zien.

AddTransient

Een nieuwe instantie telkens wanneer de container het type opvraagt. De service heeft geen eigen lijst of schermtoestand.

AddScoped

Eén instantie binnen een expliciet gemaakte scope. Een gewone MAUI-app maakt niet automatisch voor iedere pagina een scope zoals een webapp dat voor een request doet.

Een transient pagina die eenmaal gemaakt is, wordt niet spontaan vervangen bij iedere terugkeer. De navigatiestack kan datzelfde pagina-object behouden.

Laat tijdelijk het aantal gemaakte repositories zien met een breakpoint in de constructor. Vergelijk singleton met transient, voeg een grap toe en open opnieuw het formulier. Verklaar het verschil en zet de repository daarna terug op singleton.

Zie ook de Microsoft-documentatie over DI in MAUI voor constructor injection en de beschikbare lifetimes.

De bestaande pagina’s aansluiten

Vervang in AddJokePage.xaml.cs het type van het veld én de constructorparameter JokeService door IJokeService. Verwijder daar geen validatiecode. De constructor blijft de categorieën instellen.

Een pagina vragen we voortaan aan via een route. Vervang de inhoud van AppShell.xaml.cs door:

AppShell.xaml.cs
namespace JokeApp;

public partial class AppShell : Shell
{
    public AppShell()
    {
        InitializeComponent();
        Routing.RegisterRoute(nameof(AddJokePage), typeof(AddJokePage));
    }
}

Behoud in AppShell.xaml de ShellContent voor MainPage met ContentTemplate="{DataTemplate local:MainPage}". Die pagina staat al in de Shell-structuur; registreer haar niet nog eens als detailroute.

Vervang in de save-handler van AddJokePage de terugkeer met:

await Shell.Current.GoToAsync("..");

".." betekent één pagina terug in deze navigatiestack. Neem async en await over zoals in de vorige les; asynchroon programmeren zelf is geen leerdoel van deze reeks.

Het overzicht met de bestaande zoekfunctie

Onderstaande versie is een gezamenlijk vertrekpunt, inclusief de verplichte zoekfunctie uit de thuisopdracht. Vergelijk ze met je eigen oplossing; behoud bijkomende werkende uitbreidingen en styles.

MainPage.xaml
<ContentPage xmlns="http://schemas.microsoft.com/dotnet/2021/maui"

        <Grid Grid.Row="3" ColumnDefinitions="*,Auto" ColumnSpacing="8">

MainPage.xaml.cs
using JokeApp.Models;
using JokeApp.Services;

namespace JokeApp;

public partial class MainPage : ContentPage
{
    private readonly IJokeService _jokeService;
    private string _appliedSearchText = string.Empty;

    public MainPage(IJokeService jokeService)
    {
        InitializeComponent();
        _jokeService = jokeService;
    }

    protected override void OnAppearing()
    {
        base.OnAppearing();
        RefreshJokes();
    }

    private void RefreshJokes()
    {
        var jokes = _jokeService.Search(_appliedSearchText);
        jokesCollectionView.SelectedItem = null;
        jokesCollectionView.ItemsSource = jokes;
        selectedJokeLabel.Text = "Selecteer een grap.";
        countLabel.Text = $"{jokes.Count} van {_jokeService.GetAll().Count} grappen";
    }

    private void OnSearchClicked(object? sender, EventArgs e)
    {
        _appliedSearchText = searchEntry.Text?.Trim() ?? string.Empty;
        RefreshJokes();
    }

    private void OnShowAllClicked(object? sender, EventArgs e)
    {
        searchEntry.Text = string.Empty;
        _appliedSearchText = string.Empty;
        RefreshJokes();
    }

    private void OnJokeSelectionChanged(
        object? sender, SelectionChangedEventArgs e)
    {
        var joke = e.CurrentSelection.FirstOrDefault() as Joke;
        selectedJokeLabel.Text = joke?.Text ?? "Selecteer een grap.";
    }

    private async void OnAddJokeClicked(object? sender, EventArgs e)
    {
        await Shell.Current.GoToAsync(nameof(AddJokePage));
    }
}

Er staat geen new JokeService of new AddJokePage meer in de pagina’s. Shell kan de geregistreerde pagina met haar dependencies laten maken.

Test nu toevoegen, terugkeren, zoeken, een lege resultatenlijst en dubbele invoer. Typ ook een andere zoektekst zonder op Zoeken te klikken en navigeer heen en terug. De toegepaste zoekopdracht blijft bepalend; tekst in het invoerveld is niet automatisch een uitgevoerde zoekopdracht.

Grappen bewaren met LiteDB

Sluit de app volledig en start haar opnieuw. De zelf toegevoegde grappen zijn weg: een singleton leeft slechts zolang de applicatie draait. Een singleton is geen permanente opslag.

We gebruiken LiteDB, een documentdatabase in één lokaal bestand. Installeer het NuGet-package LiteDB. Dit is geen aparte databaseserver. Voor deze oefening houden we de bewerkingen klein en synchroon; grotere of tragere opslag vraagt bijkomende aandacht die buiten deze les valt.

Maak een tweede implementatie van hetzelfde contract:

Repositories/LiteDbJokeRepository.cs
using JokeApp.Models;
using LiteDB;

namespace JokeApp.Repositories;

public sealed class LiteDbJokeRepository : IJokeRepository, IDisposable
{
    private readonly LiteDatabase _database;
    private readonly ILiteCollection<Joke> _jokes;

    public LiteDbJokeRepository(string databasePath)
    {
        _database = new LiteDatabase(databasePath);
        _jokes = _database.GetCollection<Joke>("jokes");
    }

    public IReadOnlyList<Joke> GetAll() =>
        _jokes.FindAll().ToList();

    public Joke? GetById(Guid id) => _jokes.FindById(id);

    public void Add(Joke joke)
    {
        ArgumentNullException.ThrowIfNull(joke);
        _jokes.Insert(joke);
    }

    public bool Remove(Guid id) => _jokes.Delete(id);

    public void Dispose() => _database.Dispose();
}

LiteDatabase beheert het bestand. ILiteCollection<Joke> biedt bewerkingen op de collectie "jokes". LiteDB vertaalt onze objecten naar documenten en terug; de repository verbergt die API voor de rest van de app.

De property Id wordt volgens LiteDB’s naamconventie de document-id. De bestaande constructor Joke(string text, JokeCategory category) kan bij het teruglezen gebruikt worden omdat de parameters bij de documentvelden passen. We voegen geen lege constructor toe die een ongeldig model zou toelaten. Zie LiteDB: object mapping.

IDisposable laat het databasebestand sluiten. Omdat de container de repository beheert, hoort een pagina hier geen using rond haar service of repository te plaatsen.

Eén registratie vervangen

Vervang uitsluitend de registratie van IJokeRepository in MauiProgram. Registreer niet beide implementaties tegelijk voor hetzelfde contract.

builder.Services.AddSingleton<IJokeRepository>(_ =>
{
    var databasePath = Path.Combine(
        FileSystem.AppDataDirectory, "jokes.db");

    return new LiteDbJokeRepository(databasePath);
});

De factory maakt het object en geeft het bestandspad door. Alleen het samenstelpunt kent FileSystem.AppDataDirectory; de repository zelf hoeft niets over MAUI te weten.

De nieuwe database begint leeg. Dat is een geldige toestand, geen fout. Voeg via het formulier enkele grappen toe, sluit de app helemaal af en start opnieuw. Herhaald opstarten mag geen kopieën van startgrappen invoegen.

Dit wisselt de opslagimplementatie, maar migreert geen gegevens uit de oude in-memory lijst. Beide repositories hebben hun eigen gegevens.

Controleren dat het contract echt werkt

Voer met beide registraties dezelfde handelingen uit:

  1. Voeg een geldige grap toe en controleer de teller.

  2. Probeer dezelfde tekst met andere hoofdletters. Verwacht een melding en geen extra record.

  3. Zoek een deel van de tekst en controleer de toegepaste filter na navigatie.

  4. Zoek iets dat niet bestaat. De lege resultatenlijst moet bruikbaar blijven.

  5. Vergelijk het gedrag na het volledig herstarten van de app.

Plaats een breakpoint in JokeService.Add en vervolgens in de concrete repository. Volg één klik op Opslaan door alle lagen. Wijs aan waar invoervalidatie, uniciteit, opslag en schermfeedback plaatsvinden.

Dat we hiervoor geen formulier of zoekmethode moesten herschrijven, is de concrete winst van Protected Variations. Een interface is geen doel op zich: hier beschermt ze de app tegen een echte variatie in opslag.

Thuisopdracht - Verwijderen zonder de lagen te doorbreken

Werk verder in deze JokeApp. De service en beide repositories ondersteunen verwijderen al; jij sluit die bewerking aan op het overzicht.

Must

  • Voeg een knop Verwijderen toe voor de geselecteerde grap, met de bestaande DangerButtonStyle.

  • Zonder selectie is de knop niet beschikbaar. Laat de beschikbaarheid mee veranderen bij selectie en vernieuwen.

  • Laat de pagina uitsluitend IJokeService.Remove(id) aanroepen. Gebruik het ValidationResult voor feedback; benader de repository niet vanuit de pagina.

  • Vernieuw na succes de lijst en teller met behoud van de toegepaste zoektekst. Wis ook de selectie en oude detailtekst.

  • Controleer het gedrag met in-memory opslag én LiteDB. Lever de app op met LiteDB als actieve registratie.

Should

  • Toon een bevestiging voordat je definitief verwijdert. Een dialoogaanroep mag je als vast navigatieachtig recept overnemen.

  • Maak onderscheid tussen een lege verzameling en een zoekopdracht zonder resultaten.

  • Laat de knoppen ook in een smaller venster bruikbaar blijven.

Could

  • Schrijf een servicetest met een zelfgemaakte testrepository voor toevoegen, dubbele tekst en een onbekende id.

  • Verklaar in enkele zinnen waarom twee transient services toch dezelfde grappen zien.

Controle vóór de volgende les

Voeg toe, zoek, verwijder de laatste zichtbare grap en herstart. De teller klopt, een oude selectie blijft niet staan en de verwijdering is bewaard. Ongeldige invoer blijft pas na Opslaan een melding opleveren.

Bewaar deze versie. In de volgende les vervangen we events en rechtstreekse control-updates door binding en commands; de repository, service en validatieregels blijven behouden.
